# 0001 — GPUI rewrite as a separate app

Date: 2026-11-06. Status: accepted by the owner after grilling.

## Decision

Rewrite AI SubHub in Rust with GPUI as a separate repo (MIT). The C# app stays untouched; the two are compared later and one wins. **Outcome 2026-11-07 (owner)**: the GPUI app wins and takes over the name: repo and folder `ai-subhub` (GitHub `wellbrained/ai-subhub`, public for self-updates), app "AI SubHub", exe `ai-subhub.exe`, data `%LOCALAPPDATA%\AI SubHub`. The C# app became `ai-subhub-old` (repo and folder; its data moved to `%LOCALAPPDATA%\AI SubHub (old)`; its Start with Windows entry removed).

- **Scope**: core slice first: tray, popover with usage, Claude and Codex readers, refresh with retry/cooldowns, account management, display settings, hub integration. Projects, Launch menus, billing reminders, startup at login and macOS come only if the comparison favors GPUI. Data model open for more providers (e.g. Cursor) and token/cost totals.
- **Platform**: Windows first; Mac-specific code behind a seam.
- **Coexistence**: own settings file; one-time read-only import of accounts and projects from the C# settings. Superseded 2026-11-07: AI SubHub is a standalone tool, the import is removed (it was only for the owner's own move; done).
- **Rules**: same behavior rules and domain words as the C# app (`CONTEXT.md`).
- **Design**: fresh, modern design. Main surface is a borderless tray popover (closes on focus loss) with tabs **Priority** (Pinned / Running out / Used up, ring gauges) and **All Usage** (provider cards with bars). Settings in a separate window (left category menu, one column). Running-out threshold default 25% left. Tray icon is a live-drawn ring of a chosen metric (default lowest % left of pinned windows), colored as it runs low; hover shows a summary.
- **Display settings**: % left/used; ring or bar; threshold; relative/exact resets; plan badges and emails on/off; compact/comfortable density; light/dark/system + accent; tray metric; refresh interval.
- **Management**: rename, reorder, hide an account or single window, pin windows, groups (e.g. Work/Personal).
- **Hub (CLIProxyAPI on the hub PC)**: when reachable, accounts are discovered from `GET /v0/management/auth-files` and usage is read via `POST /v0/management/api-call` (hub injects the token with `$TOKEN$`), never by reading its auth files. Default `http://127.0.0.1:8317`, Tailscale URL optional. Management key entered once in Settings, stored in Windows Credential Manager. Accounts in both places merge by email: hub first, CLI profile as fallback; launches still use the profile. Benched (disabled) hub accounts show as Benched. Read-only for now.
- **Stack**: `gpui-pre` =0.3.11 + `gpui-component` =0.9.0 (exact pair); own tray module on the `windows` crate; `reqwest`, `serde`.
- **Spike first**: tray with live ring icon, popover above the tray with focus-loss close, app alive without windows, one real hub read, idle memory. A bad failure stops the work for a new decision.
- **Comparison** (`docs/comparison.md`): startup time, idle memory, download size, idle CPU in tray, look and feel, ease of change.
- **Tracking**: version 0.1.0.

## Reason and tradeoffs

## Refinements 2026-11-06 (after the first build and previews)

- **Main layout**: back to the old app's structure (preview A "Classic, refined"): provider headings, one card per account (name, plan pill, freshness, source tag), one row per window with label, bar, "% left", reset. Replaces the Priority/All Usage tabs. Pace/forecast views were dropped (owner: not needed).
- **Source tags**: text tags "Hub", "CLI" (both when merged), "Direct" for profile-only accounts, struck-through "Hub" + "benched" for benched logins. Revised 2026-11-07: the "CLI" pill is dropped (hub login + CLI profile is the normal case and read as a duplicate); profile-only accounts say "Local only".
- **Popover** stays open until the tray icon, Esc or ✕ (setting restores close on focus loss); native DWM corners; 12 px from the work-area edges.
- **Taskbar display** (always visible): a small window attached to the taskbar (TrafficMonitor-style; Windows has no official API, so it can break with updates; falls back to a floating window above the taskbar; the tray icon stays). Modes: Bars (5h/W labels), Table (B1), Blocks (B2), Mix (number with % + bar). Position next to the tray (default since the owner's taskbar is left-aligned, where the left spot collides with icons) or left by the widgets/weather; draggable along the taskbar, position remembered. Values are % left (follow the usage-style setting). Click opens the popover.
- **Hub steering (supersedes "hub is read-only")**: SubHub may change exactly one thing in the hub, each account's credential priority (`PATCH /v0/management/credentials/fields` `{name, priority}`, as the hub's own UI does). Clicking an account's Hub tag makes it the preferred account; clicking again returns to Auto. Auto picks the hub account whose weekly leftover is most at risk of expiring (% left ÷ hours to weekly reset), skipping benched, 5-hour-exhausted (<5% left) or stale accounts, tie-break by more 5-hour room, with hysteresis. Original priorities are remembered and restored when steering is turned off. Applies to every hub client (T3 Code's Hub provider, other hub-backed CLIs and servers) for new threads; session affinity keeps running threads on their account. Nothing else in the hub is written (no benching, logins, config).

- **Cooldowns are per login (2026-11-06)**: one account's hub login got repeated 429s from the usage endpoint while the same account's CLI-profile login (old SubHub) read fine. For an account that has both, a hub 429 starts a cooldown for the hub path only; SubHub then reads the profile and does not call the hub for that account until the cooldown ends. A login that is cooling down is never called again early.

- **Logo and icons (2026-11-06)**: logo = static "skeleton badge" (concept S4 colours, never live): Claude-orange provider dot with an orange tag pill under it, a long blue bar over a short amber bar, on a 16 px grid. Same mark for tray, window, Start and exe. Text characters used as icons (✻ ◎ ↻ ⚙ ✕ ☆ ↑ ↓) are replaced by drawn SVG icons in one consistent stroke.
- **App icon "Night glow" (owner, 2026-11-07)**: the app icon (window, title bar, exe, Start) becomes `crates/subhub-app/assets/logo.svg`: the same skeleton badge on a violet squircle with glowing gradient bars and an orange orb, the tag pill overlapping the orb as before; rendered with resvg (exe .ico 16-256 px, window icon) and shown as an image in the merged title bars. The tray keeps a simple version (no tile, no bar tracks) on the 16 px grid, because the full icon does not read at tray size.
- **Settings rework (2026-11-06)**: left menu = General, Display, Taskbar, Hub & steering; then a clearly separated provider section with every account as its own page (tag chip + name); "+ Add account" and About pinned at the bottom. Account pages save on change (no Rename / Set tag buttons). Replaces the list-plus-editor-below Accounts page (too much scrolling).
- **Sign-in, billing reminders, startup (2026-11-07)**: the "only if the comparison favors GPUI" deferral is lifted for three C# features, ported with the same rules: per-account Sign in (provider CLI login for the profile in Windows Terminal or PowerShell, then an automatic refresh) and Retry (skips failure backoff, never a provider cooldown), Settings → Tools (terminal, CLI paths); optional manual monthly renewal / access end date with 7- and 3-day reminders and an "Open billing" link; opt-in Start with Windows (HKCU Run, "AI SubHub"). Details: `docs/features/app.md`.
- **Projects and Launch ported (2026-11-07)**: the deferral of Projects and the Launch menus (Scope, above) is lifted for them, ported from the C# app with the same behaviour rules: saved local folders shared by all accounts (Settings → Projects: reorder, Show/Hide, rename, Remove = shortcut only, no duplicates), and a rocket button in each popover account card that opens that account's Launch menu (visible projects, each with Windows Terminal / PowerShell / VS Code / the provider's desktop app, then "Manage projects…"). Details: `docs/features/app.md`.


- **Usage statistics (2026-11-07)**: a separate Statistics window (opened from the popover header and the tray menu) modelled on T3 Code's usage board: range (24h / 7 / 30 / 90 days), Cost / Tokens / Limits, big total with provider split, daily chart, totals, cost by type, breakdown by model or day. Data from the CLIs' local session logs (Claude Code `projects/**/*.jsonl` usage per message; Codex `sessions/**/*.jsonl` token counts), per provider and model only: the owner's Claude account folders share one `projects` folder and hub sessions write there too, so per-account needs the hub's usage statistics (later). Cost = API estimate; prices are automatic and read-only (LiteLLM's public price list, fetched daily, the same source ccusage uses, over a built-in fallback table; no manual overrides); unknown models show "Unpriced". Background scan with an incremental per-file cache; never blocks the popover or taskbar. Reading history is saved from now on. Update (owner, 2026-11-07): the Limits tab now copies T3 Code's live limits board (latest readings per provider, window kind and account), and the history line chart was dropped.
- **Hover cards and taskbar monitors (owner, 2026-11-07)**: (1) The taskbar display gets its own on/off switch ("Show usage next to the tray", the style is kept); the style "Off" is gone. (2) Hover cards replace the native tray tooltip: our own popover-styled window via `NOTIFYICON_VERSION_4` without `NIF_SHOWTIP` (`NIN_POPUPOPEN`/`NIN_POPUPCLOSE`, plus a cursor watchdog and a `WM_MOUSEMOVE` fallback because Windows does not always send them), and one per taskbar badge; the text tip stays set for screen readers; a switch brings back the plain tooltip. Windows 11 has no public API for rich tray flyouts, so an own window is the only way. (3) The taskbar display can show on the main taskbar, all taskbars or chosen monitors; monitors are saved by device path; a missing chosen monitor falls back to the main taskbar; drag positions are per monitor; hover cards work on every taskbar. Reason: the grey text tip was hard to read and could not show both windows, resets and state; multi-monitor setups want the usage where they look. Pure parts (card content, tip text, monitor choice, card placement) live in core with tests.
- **Updates (owner, 2026-11-07)**: SubHub updates itself. (1) Source: GitHub Releases of `wellbrained/ai-subhub` (`releases/latest`, tag `vX.Y.Z`, assets `ai-subhub.exe` and `.sha256`), HTTPS only, newer versions only, "no release" is not an error; no update server of our own. (2) Settings -> Updates with an Auto / Manual switch: Auto checks at start (after ~1 min) and every 6 h, downloads in the background and installs when idle; Manual only shows "Update available" with an Install button. (3) Install = download to `%LOCALAPPDATA%\AI SubHub\updates`, verify SHA-256, rename the running exe to `<exe>.old`, copy the new one to the same path (so Start with Windows keeps working), start it with `--updated-from <old> --wait-pid <pid>` and quit; a failed swap is rolled back ("Cannot update in this folder"); development builds under `target\debug|release` never install. (4) Restart only when idle (no popover, Settings, Statistics or notes window, no sign-in, no popover drag; retried each minute), while a Manual Install runs at once. Patch notes come from `CHANGELOG.md` (embedded in the exe) and show once after an update in a small dialog, skipped versions included. Reason: the owner builds and deploys by hand today and wants the same flow for other machines without a store or installer; the checksum guards against a broken or partial download, not against a compromised release (no code signing yet).
- **Statistics redesign and merged title bar (owner, 2026-11-07)**: (1) Statistics and Settings drop the Windows caption bar (it looked foreign in light mode) for one 46 px bar in the app's colours: logo, title, tabs, range switch, Copy as image, Rescan and our own minimize / maximize / close (46 px, close hover `#c42b1c`). Built on GPUI's own support: `TitlebarOptions { appears_transparent: true }` plus `WindowControlArea` hit areas (`Drag` = `HTCAPTION`: Windows moves the window, maximizes on double click, snaps; `Min`/`Max`/`Close` = native button hit codes, so the snap layouts flyout appears on the maximize button); resizing stays with the window frame and GPUI's top-edge hit test. gpui-component's `TitleBar` was not used (34 px bar and buttons, different look). Drag areas are siblings of the controls, never their ancestors. DWM rounding and border helpers stay. (2) Tabs are `Usage | Limits` (Cost and Tokens merged); the window opens on Usage; Limits unchanged. The window title for taskbar and alt-tab stays "AI SubHub · Statistics". (3) Usage view, from the approved previews A + B: tiles (Work tokens with a provider split bar, Served from cache with the cache hit rate, API estimate, Cache saved, run-rate = this month's cost so far scaled linearly to month end), a compact "By type" table, and a Breakdown switch Models | Providers | Days (remembered in `settings.stats`, with the chart metric Tokens | Cost; `#[serde(default)]`). **Work tokens** = input + output + cache writes; cache reads are shown separately because they are ~98% of all tokens and hide the real work. The daily chart is stacked by provider (Claude bottom, Codex top, 2 px gap), starts at the first day with data and has a tooltip per day; share bars follow the Tokens / Cost switch. (4) Provider colours (checked with the dataviz palette validator): light Claude `#c96a4a`, Codex `#3f74cc`; dark `#d07052` / `#4f84dc`. Codex was the text colour before, which failed. Only dots, bars and marks carry them, never text. (5) The window height is fitted once to the Usage content in the Models view and never changed by switching tabs or views.
- **Profile detection (owner, 2026-11-07)**: SubHub finds the CLI profiles on the PC by itself and offers them on first start (Settings opens on Detect / Import) and later from Settings. Places: `~\.claude*` / `~\.codex*` folders, `CLAUDE_CONFIG_DIR` (comma list) and `CODEX_HOME`, and `.config\claude`. The environment variables and the `.config` location were checked against the places ccusage looks at (as a reference only; nothing copied); the `-suffix` folders come from the owner's multi-account setup. Only the login email is read (as Add account does). A detected folder is never imported twice, and a login already connected through another folder is shown but cannot be imported. Hub logins stay automatic (added on every refresh) and are only listed read-only, so the hub merge is unchanged. Detection is manual (page open, Detect again): no background watching, no ignore list. This is generic discovery, not the removed one-time C# import.

The owner wants to compare a GPUI build against the working Avalonia app rather than replace it blindly. A separate repo and settings file keep the daily-use app safe. GPUI has no tray or window hide API and its crates.io release is stale, so the community snapshot pair is pinned and the risky platform parts are proven in a spike before features. Reading through the hub's API keeps token renewal with the hub (two token owners would cancel each other's renewals) and removes manual account setup. Accessibility in GPUI is experimental; accepted for a personal comparison build.
