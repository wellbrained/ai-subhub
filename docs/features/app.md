# App: tray, popover, taskbar display, steering, settings

Crate `crates/subhub-app` (GPUI). Domain logic lives in `crates/subhub-core`; the app only renders state and calls core on background threads. Decisions: ADR 0001 (incl. "Refinements 2026-11-06").

## Lifecycle

- One instance (named mutex `Local\AISubHub.SingleInstance`); a second start exits.
- `QuitMode::Explicit`: closing windows keeps the app running; Quit is in the tray menu and Settings → General. If the tray icon cannot be created the app quits at once.
- First start with no accounts opens Settings on Detect / Import.

## Logo and icons

- Logo (`logo.rs`): static skeleton badge on a 16-unit grid (Claude-orange dot, orange tag pill overlapping its lower edge with a small gap, long blue bar over short amber bar on grey tracks), rendered with 4x4 supersampling. Used for the tray icon (32 px, never live), window icons (`logo::window_icon`, 64 px) and the exe (`assets/app.ico`, 16–256 px PNG entries, written by `ai-subhub --write-icon <path>`, embedded by `build.rs` via `app.rc`). Regenerate the .ico after changing the geometry.
- UI icons (`icons.rs`): Lucide SVGs from gpui-component's `gpui-kit-assets` (refresh-cw, settings, x, star, arrows, plus, info, eye, trash, check) plus own provider marks (`assets/icons/provider-claude.svg`, `provider-openai.svg`), served by `assets::Assets`; single-colour, tinted via `text_color`. No text characters as icons.

## Tray icon

- Own `Shell_NotifyIconW` module (`tray.rs`, `NOTIFYICON_VERSION_4`). Left click (`NIN_SELECT`) toggles the popover; right click (`WM_CONTEXTMENU`) opens Open / Refresh usage / Settings / Quit. Only one of each click pair is handled (a click also sends `WM_LBUTTONUP`; handling both opened and closed the popover at once).
- Icon: the static logo. Tooltip: lowest % left per visible account, "(stale)", cut to 127 chars.

## Popover (layout A)

- Borderless `WindowKind::PopUp`, opaque, native Windows 11 rounded corners/outline/shadow via DWM (`window_style.rs`). 460 px wide; height fits the content (240–720 px, more scrolls) and re-fits upwards via `SetWindowPos` when content changes (GPUI `resize` keeps the top edge). The current height is read from `GetClientRect`: GPUI's viewport size lags a frame, and quick changes (Density toggled back and forth) piled up stale deltas until the popover collapsed. Centred on the tray icon (or the notification area when the icon is in the overflow), 12 px inside the monitor work area.
- Stays open until the tray icon, Esc or ✕; Display → "Close popover when clicking elsewhere" (off by default) restores close-on-focus-loss with a 300 ms reopen guard.
- Header: "AI SubHub", "Updated … · next in …" (or Updating… / hub key problem), ↻ (refresh now: skips backoff, never a provider cooldown), ⚙ Settings, ✕.
- Provider headings, one card per visible account: name, plan pill, group, source tags, status tag (Stale / Cooling down / Sign in needed / CLI missing), freshness dot + "Xm ago"; one row per visible window: label, bar, "% left" (or "% used"), reset. Stale cards are dimmed with the last reading time and message; cards without a reading this session explain the saved schedule ("Usage checks cooling down · next try in …").
- Source tags: **Hub** (clickable, see steering; "★ Hub · preferred" when picked, "Hub · next" for the current Auto target), **Hub · benched**, **Local only** (CLI profile, not in the hub). A CLI profile next to a hub login gets no pill (owner, 2026-11-07: both are the normal case; Settings still names the source).

## Taskbar display

- `taskbar.rs`: borderless, topmost tool window over a free part of the taskbar (Windows has no API for third-party taskbar content; TrafficMonitor-style). Right (default): left of `TrayNotifyWnd`, or 380 px from the right edge when Windows 11's XAML taskbar has none (this PC); Left: 176 px from the left edge (centred taskbars only; collides with left-aligned icons). Drag it along the taskbar to move it; the spot is saved as `taskbar_offset` (px from the taskbar's right edge) and choosing Left/Right resets it. A short press without moving is a click. Starts 2 px below the taskbar top so its top border stays visible, then fills the rest; re-raised every second (the taskbar comes to the front when clicked), and hidden while a fullscreen app is in front (`SHQueryUserNotificationState` busy/D3D/presentation, or the foreground window covers its monitor; desktop and taskbar excluded). Before this it covered fullscreen videos and games (owner, 2026-11-06); verified hidden with Chrome fullscreen. Vertical/hidden taskbars are not supported. Click toggles the popover.
- Style (Display → Taskbar display): Off, **Badge** (default; like T3 Code's provider tags: left block over both rows = provider icon (Claude orange ✻, Codex ◎) with the coloured two-letter account tag overlapping its bottom-right corner, 1:1 the T3 Code sidebar style (owner, 2026-11-06), right block = "5h bar %" over "W bar %"; integrated like tray icons (owner, 2026-11-06): no boxes, full height, rounded hover highlight per badge, thin dividers left and right of the group, tag centred on the icon's bottom edge, steering target marked by a small accent bar under the icon like Windows' running-app marker (under the whole badge it read as a third row); labels no-wrap (a 12 px column broke "5h")), Bars (name + %, then the 5-hour bar), Numbers ("5h% · W%" over the name, clock-like), Focus (one account: the pair over "name · +N ready"). Old Mix/Blocks load as Bars, Table as Numbers.
- Typography matches the taskbar clock (owner, 2026-11-06): Segoe UI Variable Text, 12 px, regular, two 16 px lines, full-contrast text. No fill: the window is transparent and skips gpui-component's `Root` (it paints the theme background); `window_style::no_frame` removes the Windows 11 popup frame (border colour none, no rounding). Faint fill only on hover. Verified 2026-11-06: pixels inside the display match the taskbar next to it, so custom taskbar colours show through. Text/bar colours follow the Windows mode (`SystemUsesLightTheme`, taskbar/Start), not the app mode, re-checked every second.
- How many (Display → How many on the taskbar): 1–5, default 3.
- Tags: own tag per account in Settings → Accounts (1–3 characters, kept as typed, empty = automatic two letters from the short name); stored in `settings.account_tags`. Colour stays fixed per account id. Example: WRK, PER, SID.
- Which accounts (Display → Taskbar shows): Favorites (default; ☆/★ on each popover card, first N in star order, shown even before their first reading with "—"; the steering target when none is starred), Focus (steering target only), Auto (steering target + accounts at or below the running-out threshold, max 3). Never blank: falls back to the first account with a reading. The steering target gets a dot. Short names: the part after " · " of auto-made labels ("gmail"), else 10 chars.
- `window_style::set_bounds` corrects for the popup's invisible frame (`SetWindowPos` takes the outer rect); without that every re-place after a refresh moved the display ~10 px up, half above the taskbar (seen 2026-11-06).
- GPUI's default line height is too tall for three lines in a ~40 px taskbar; the display sets 11 px.

## Hub steering

- After each refresh and on Hub-tag clicks, `AppState::steer`: `steer::target` (off → none; preferred → it; else Auto: highest weekly % left ÷ hours to weekly reset among hub accounts that are not benched/hidden/stale and have ≥ 5% of the 5-hour window, 25% hysteresis) → `steer::plan` → background `HubClient::set_priority` (`PATCH /v0/management/credentials/fields {name, priority}`, fallback `auth-files/fields` on 404). Originals are saved only after all writes succeed; failures show in Settings → Hub.
- Verified 2026-11-06 on the installed hub: Auto picked the account whose weekly reset came first and the hub listed `priority=100` for it, others unchanged.
- Applies to new threads of every hub client (T3 Code's Hub provider, other hub-backed CLIs and servers, Codex Hub); session affinity keeps running threads on their account. Turning steering off restores original priorities.

## Settings window

Left menu, one content column (owner rule); 900x640 by default.

- Top group: General (refresh interval, close button, Start with Windows), Display (theme, accent, % left/used, running-out threshold, reset times, density, plan badges, emails, close popover on focus loss), Taskbar (style, how many, which accounts, position), Hub & steering (hub on/off, status, steering on/off and "Steering now", address, management key).
- Accounts section below a divider: provider headings (icon + uppercase name), one entry per account with its tag chip and name (hidden accounts dimmed). "+ Add account" (provider, name, profile folder), "Detect / Import" and About are pinned at the bottom; only the account list scrolls.
- Account page: header (tag, name, email, provider, plan, source), Name and Taskbar tag (save on Enter, blur or page switch, only when changed), Show on taskbar, Preferred for new hub threads (hub accounts), Group chips + new group, per-window Pin/Hide, Order (up/down), Hide/Show, Remove (second click confirms).
- Rows wrap: label (min 240 px, hint wraps) and control side by side when they fit, else the control moves to its own line, right-aligned (chips clipped "25%" before).
- Toast (owner, 2026-11-07): a small raised card floating centred over the bottom of the content column, icon by kind. "Saved" (check) for ~2 s after a user change (`AppState::save_user` bumps `user_saves`; refreshes use `save`), an action message (info, e.g. "Linked the profile to Personal …") for ~4 s, problems (settings file, hub steering) until dismissed with ✕. Replaced the permanent footer bar.

## Refresh

`AppState::refresh`: list the hub (when on and a key is stored) → `merge::apply_hub_accounts` → read due accounts in parallel threads (`refresh::read_account`: hub first, profile fallback) → apply results (schedule, reading, email, plan) → `merge::fold_duplicates` → save → steer. A 30 s timer calls it; each account's persisted schedule decides whether it is due.

- Hub cooldown per login: a hub 429 for an account that also has a CLI profile reads the profile in the same round and skips the hub for that account until `retry_after` (default 10 min); `AppState::hub_cooldown`, not persisted. Folding keeps tag, star and steering choice.
- A 401/403 through the hub means the hub's login was not accepted (seen 2026-11-06: Codex `token_expired` on a hub login never used through the hub). SubHub never renews tokens.
- No duplicates (owner rule, 2026-11-07): Add account reads the profile's login email from its own metadata (`profile::profile_email`: Claude `.claude.json` oauthAccount.emailAddress; Codex `auth.json` id_token payload, email claim only) and attach the profile to the existing account with that email (keeping name, tag, star, order, readings); an already connected folder or a login that already has a profile is skipped.
- Tag colours: 8 clearly different hues; each account prefers the slot from its login email (stable across merges), else the id, and takes the next free slot when an earlier account (settings order) has it, so no two accounts share a colour (`taskbar::tag_slot`).
- `fold_duplicates` merges a hub-only account into a profile account that just learned the same email (a profile whose email is not known yet).

## Detect / Import (2026-11-07)

Core: `subhub-core/src/profile.rs` (`discover_dirs`, `profile_email`), `subhub-core/src/detect.rs` (statuses, `attach_profile`, `import`, `default_label`). UI: Settings -> Detect / Import (`settings_window.rs`), `AppState::detect_profiles` / `import_profiles`. Decisions: ADR 0001 ("Profile detection").

- **Where**: every folder in the user folder whose name starts with `.claude` / `.codex` (sorted, so the defaults come first), then the folders in `CLAUDE_CONFIG_DIR` (comma-separated, `~` expanded) and `CODEX_HOME`, then `%XDG_CONFIG_HOME%\claude` or `~\.config\claude`. Canonical (junctions resolved), stored without the `\\?\` prefix, each folder once per provider. The statistics scan uses the same `discover_dirs` (and keeps only `projects` / `sessions`).
- **What counts**: Claude folders with `.claude.json` or `projects`, Codex folders with `auth.json` or `sessions`. The email comes from `profile_email` only (no token is read or kept); the default `~\.claude` falls back to `~\.claude.json`, where Claude Code keeps it without `CLAUDE_CONFIG_DIR` (this also fixes Add account for that folder).
- **Rows** (grouped by provider): checkbox, email in bold (folder name when none), path, status tag: **New**, **Joins "<name>"** (an account with this email but no profile, usually a hub account; it keeps name, tag, star, order and readings), **Already added as <name>** (no checkbox, dimmed), **Same login as <folder>** (a connected or earlier folder has this login; never imported), plus **No login found** for folders without an email. New / Joins rows with an email are ticked when the page opens; no-login rows are importable but unticked.
- **Hub**: a read-only HUB block with the hub status ("4 logins in the hub, added automatically on each refresh", or what is missing, with a Hub & steering button) and one row per hub account (Hub · added automatically / Hub + profile / Hub · benched). Hub logins are not imported here: `merge::apply_hub_accounts` adds them on every refresh, as before.
- **Actions**: Select all, Select none, Detect again, **Import selected (N)**. Ticking saves nothing (the one exception to save-on-change, like Add account); Import attaches each pick through `detect::attach_profile` (also used by Add account, so the no-duplicates rule lives in one place), saves, refreshes, opens the first new or linked account and shows a toast ("Imported 2, linked 1 to existing accounts."). Names: the email's local part, with the domain when the provider already has that name ("me · corp"), else the folder name without the dot.
- **When**: detection runs each time the page opens and on Detect again, and the statuses are recomputed when the account list changes while the page is open (ticks on rows that stay importable are kept). Without that, a first start showed "New" for profiles whose hub login the first refresh added a moment later (seen 2026-11-07); no background watching, no ignore list (a removed profile shows as New again). No profiles found: a hint with an Add account button.
- Verified: tests in `profile.rs` and `detect.rs`; a read-only dry run on the owner's PC (2026-11-07) found `.claude`, `.claude-gmail`, `.claude-gmail-tavora` and `.codex` with logins, and `.claude-hub`, `.claude-sub-gmail` and `.codex-hub` without. Not yet run in the UI (the installed app held the single-instance mutex).

## Sign in, Retry and Tools

Core: `subhub-core/src/launch.rs` (pure command building, tested without a terminal), UI in `settings_window.rs`, `popover.rs`, `state.rs`.

- **Sign in** (account page, and the popover card when the last check said sign-in needed): starts the provider CLI login (`claude auth login --claudeai`, `codex login`) for the account's profile. `LaunchPlan`: Windows Terminal (`wt new-tab powershell.exe …`) or `powershell.exe -NoLogo -NoProfile -NoExit -EncodedCommand <base64 UTF-16LE script>`; the script clears the 11 billing/auth override variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, …), sets `CLAUDE_CONFIG_DIR` / `CODEX_HOME` to the profile folder (also in the script, because a running Windows Terminal hands new tabs its own environment), and quotes every path as a PowerShell literal (data, not code). SubHub only launches the CLI; it never reads or passes a token.
- **After sign-in**: the script writes the CLI's exit code to a unique temp file (`LoginCompletion`, as in the C# app); SubHub polls it every 250 ms for up to 10 minutes and, on exit 0, refreshes that account (`AppState::refresh_account`). Non-zero or timeout leaves a note on the account instead of claiming success.
- **Hub-only accounts** (no profile) cannot sign in from SubHub: the card and page say "Sign in through the hub".
- **Retry** (card when stale/failed, account page "Retry now"): `AppState::refresh_account(id)` forces a refresh of that account only: skips failure backoff, never a provider cooldown (`Schedule::cooling_down`; then a note shows when the cooldown ends). Asked during a running refresh, it runs right after it. Not offered for sign-in-needed accounts (Sign in instead) or during a cooldown, like the C# `UsageRecovery`.
- **Tools page** (top menu after Hub & steering): Sign-in terminal (Windows Terminal / PowerShell; Windows Terminal is auto-detected via `wt.exe` on PATH, PowerShell is used when it is missing), Claude CLI and Codex CLI path inputs (empty = auto-detect: `~/.local/bin`, npm global, PATH, Codex desktop bundle; saved on Enter or blur; must be an existing .exe/.cmd/.bat), each with "Found: path" / "Not found". The configured Codex path is now passed to `refresh::read_account`.

## Projects and Launch (2026-11-07)

Port of the C# Projects + Launch menu. Core: `subhub-core/src/projects.rs` (list ops), `launch.rs` (pure command building, `menu_targets`). UI: `settings_window.rs` (Projects page), `popover.rs` (rocket button), `state.rs` (actions). Sign-in machinery is reused: same env isolation, `LaunchPlan`, `-EncodedCommand`.

- **Project** = `{ id, label, directory, hidden }`, `settings.projects` (`#[serde(default)]`; older files load with none), shared by all accounts, the Vec order is the user's order. Same folder never twice: compared canonically (`projects::folder_key`: canonicalize when it exists, `\\?\` stripped, separators unified, trailing `\` ignored, case-insensitive on Windows). An empty label becomes the folder name; 60 characters max.
- **Settings -> Projects** (top menu after Tools): flat rows (label + path; "Hidden" / "Folder missing" tags), up/down over the full list (hidden ones keep their place, so the filtered Launch order follows), Show/Hide, Rename (pencil, one shared input, Enter or blur saves), Remove (second click confirms; only the shortcut). "Add project" uses GPUI's `prompt_for_paths` (folders, several at once). Everything saves on change with the usual "Saved" toast. The folder of an existing project cannot be changed (remove and add).
- **No C# import** (owner 2026-11-07): AI SubHub is a standalone tool; the import of accounts and projects from the C# app (General and Projects buttons, the automatic one-time project import, `subhub-core/src/import.rs`, settings flags `import_done` / `projects_import_done`) was removed. Older settings files with those flags still load (unknown fields are ignored).
- **Rocket button** (Lucide `rocket`) in each account card header, before the star, opens a **Launch dropdown**: our own floating card (272 px, popover colours and type, soft offset shadow) right-aligned under the rocket, drawn over the cards with gpui `deferred` + `anchored` and snapped inside the popover window, so the popover never resizes for it. One open at a time (`AppState::launch_open`, not saved); a press outside closes it (`launch_closed` keeps that press from reopening it via the rocket). Owner 2026-11-07: the gpui-component dropdown looked foreign and its submenus opened to the left; an inline panel pushed the cards down. Rows: one per visible project (folder icon, label, full path on hover) with four icon buttons: **Windows Terminal** (`terminal`), **PowerShell** (`square-terminal`), **VS Code** (`code-xml`), the provider's **desktop app** (`app-window`). Disabled targets are dimmed with the reason in the tooltip. "No visible projects yet" when empty; **Manage projects…** under a divider (sets `pending_settings_page`, opens Settings on Projects). Launching closes it.
- **Popover resize**: content changes re-fit the height on the next tick through GPUI's `window.resize` (so its surface follows) with the bottom edge fixed (`window_style::resize_to_bottom`: the target top is computed up front from the constant frame size, the window is moved there, then GPUI resizes downwards onto the bottom). A raw `SetWindowPos` that grew the window during a click left the new area white; reading the rect after `resize` raced GPUI and let the bottom edge wander (2026-11-07).
- **Top-edge drag** (owner 2026-11-07): a 6 px strip over the top edge (ns-resize cursor) resizes like a normal window top edge; the bottom stays. The drag polls the cursor and the left button (`GetCursorPos`, `GetAsyncKeyState`) every 16 ms, since the cursor leaves the window when dragging up; limits 240 px to the work area top (12 px margin). On release the height is saved in `display.popover_height`, which then replaces the fit-to-content height (more content scrolls). Double-click the strip to go back to fitting the content.
- **Header**: "Updated … · next in …" sits quietly (faint) right of the title area, next to the refresh button; cards no longer show their own age (stale cards keep their "Last reading …" line).
- **Launching** (`AppState::launch_target`): CLI targets run `Set-Location -LiteralPath <project>; & <cli>` in a new Windows Terminal tab or PowerShell window with the 11 override variables cleared and `CLAUDE_CONFIG_DIR` / `CODEX_HOME` = the account's profile (an explicit terminal overrides the sign-in terminal preference; all paths PowerShell literals, `-EncodedCommand`). VS Code: `code --new-window -- <dir>` through a hidden PowerShell. Claude Desktop: `claude://code/new?folder=<escaped full path>` (Claude asks to confirm the folder). Codex Desktop: starts the app (`explorer.exe shell:AppsFolder\<AppId>`) and leaves a note on the card, "Codex Desktop opened. Choose <project> there." (Windows cannot navigate it). Errors and that reminder show as the card's note and disappear after 10-15 s.
- **Disabled items with a hint** (`launch::menu_targets`, shown under the item): folder gone ("The folder no longer exists", all items), CLI missing ("CLI not found (set it in Settings -> Tools)"), Windows Terminal not found, VS Code not found on PATH, desktop app "Not installed". Hub-only accounts (no profile): CLI items say "No CLI profile: sign in through the hub"; VS Code and the desktop app still work.
- **Detection**: CLI/Windows Terminal/`code` are looked up when a menu opens (PATH and the usual folders, as for sign-in). Desktop apps are detected once at startup on a background thread, as in C#: a hidden PowerShell reads `Get-StartApps` ("Claude", "Codex") and the `OpenAI.Codex` package, 20 s timeout, then nothing is found. Items are disabled until it finishes.
- Tests never start terminals or apps: plans are built and decoded in `launch.rs` tests (each target, quoting of spaces/apostrophes/`&`/parentheses, the 11 variables, hub-only, hints, URI escaping, detection output parsing).

## Monthly billing

Core: `subhub-core/src/billing.rs`, a port of the C# `MonthlyBilling.cs`.

- Per account, optional, manual (providers expose no reliable billing date): a **Monthly renewal** date or an **Access end date** (kind chips Renewal / Access ends). Monthly only; later dates are estimates that keep the original day (Jan 31 → Feb 28 → Mar 31) and are labelled "estimated", the entered date "manual". An access end never recurs ("Ends …", "Ended …" afterwards).
- Account page → Monthly billing: date input `YYYY-MM-DD` (shows the next, possibly estimated, date; saving the shown date keeps the original anchor and the reminder history), kind chips, "Remind me 7 and 3 days before" switch, Open billing, Clear. A renewal date must be today or later.
- Popover card footer (only for accounts that track a date): "Renews Dec 1, 2026 · in 25 days · estimated" (accent colour within 7 days) and Open billing. URLs: Claude `https://claude.ai/settings/billing`, Codex `https://chatgpt.com/#settings/Account` (what the C# app uses); the browser's signed-in account may differ from the CLI profile.
- Reminders: `AppState::check_billing_reminders` at start and every 30 s; 7 days and 3 days (calendar) before, only the most urgent threshold when several were missed. The delivered (cycle date, threshold) is saved before the notice goes out, so it never repeats, also across restarts; a failed save undoes the mark and retries later. Delivery is a tray balloon (`Tray::balloon`); no OS job runs while SubHub is closed.
- Data in settings maps keyed by account id: `billing`, `billing_reminders` (moved on `fold_duplicates`, removed with the account).

## Statistics (2026-11-07)

Core: `subhub-core/src/stats/` (`parse` pure line parsers, `price` table + cost, `scan` discovery/cache/aggregation, `summary` range summaries) and `history.rs`. UI: `subhub-app/src/stats_window.rs`. Decisions: ADR 0001 ("Usage statistics").

- **Window**: opened from the chart icon in the popover header (the popover stays open next to it) and the tray menu item "Statistics" (client width 1000, titlebar "AI SubHub · Statistics"). Compact layout (16 px padding, 44 px top bar, 28 px total, 190 px chart, 34 px breakdown rows); no in-window close button (the title bar has one). When the first data arrives the window is sized once to show every section and up to 12 breakdown rows without scrolling (`content_height`, clamped to the monitor work area, centred; more rows scroll). Layout follows T3 Code's usage board: range (Past 24h / 7 / 30 / 90 days) and Cost / Tokens / Limits, big total + sessions + "API estimate" (info tooltip names the price source and date), provider rows, daily area chart (gpui-component `AreaChart`; Claude orange, Codex text colour), Totals, Cost/Tokens by type stacked bar, Breakdown by Model or Day ("Unpriced" for unknown models). "Scanning…" until the first scan is ready; a scan starts on open and on the refresh button. Top bar also has **Copy as image** (`window_style::copy_client_to_clipboard`: `PrintWindow` with `PW_CLIENTONLY | PW_RENDERFULLCONTENT` into a compatible bitmap, `CF_BITMAP` on the clipboard; "Copied to clipboard" / "Could not copy" for 2 s). Limits tab: see "Limits tab" below.
- **Data (local logs, per provider and model only)**: Claude Code `projects/**/*.jsonl` under every Claude profile folder from `profile::discover_dirs` (`%USERPROFILE%\.claude*`, `CLAUDE_CONFIG_DIR`, `.config\claude`) (the account folders share one `projects` junction: roots are canonicalized and deduplicated), lines `type == "assistant"` with `message.usage` {input_tokens, output_tokens, cache_creation_input_tokens, cache_read_input_tokens}, `message.model`, `timestamp`, `sessionId`; deduplicated by `message.id` + `requestId` (streamed messages repeat; first wins). Codex `sessions` and `archived_sessions` of every Codex profile folder (`%USERPROFILE%\.codex*`, `CODEX_HOME`) (`.jsonl` and `.jsonl.zst`, which Codex compresses): `turn_context.payload.model` and `event_msg/token_count` `info.last_token_usage` / `total_token_usage` {input_tokens (includes cached), cached_input_tokens, cache_write_input_tokens, output_tokens}; per-request deltas of the running total (duplicate events add nothing, a counter reset falls back to `last_token_usage`). Normalized to uncached input / cache read / cache write / output; "processed" is the sum. Days are local time; buckets are hourly (24h range).
- **Privacy**: only usage, model, timestamp and session fields are declared for serde; message content is never parsed, kept, logged or reported. `--stats-dump [path]` prints aggregate numbers only.
- **Cache** `%LOCALAPPDATA%\AI SubHub\stats-cache.json`: per file path, size, mtime, byte offset (up to the last complete line), aggregated buckets, sessions, dedupe hashes, Codex model/previous total. Later scans read only appended bytes; a shrunk file (or size/mtime disagreeing) is read again; `.zst` files are read whole when new or changed; vanished files drop out (an archived Codex session is the same data under a new path). Scan runs on a background executor thread with a few worker threads; first real scan of ~1600 files / ~3 GB: ~1.8 s, incremental ~80 ms.
- **Cost = API estimate**: prices are automatic and read-only. Layering (`stats/prices.rs`): fetched LiteLLM list, then the built-in table (`price.rs`, USD per million tokens: input, output, cache write, cache read; source/date in its comment), else Unpriced (tokens yes, cost no). ## Updates (2026-11-07)

Core: `subhub-core/src/update.rs` (versions, release JSON, sha256 lines, dev-build check, idle decision, start arguments, the two blocking network calls), `swap.rs` (exe swap through an `Ops` trait, tested with a fake), `changelog.rs` (parser). App: `updater.rs` (status, background threads, restart), `whats_new.rs` (dialog), Settings -> Updates in `settings_window.rs`, a 60 s tick `spawn_updater` in `main.rs`. Decisions: ADR 0001 ("Updates").

- **Source**: `GET https://api.github.com/repos/wellbrained/ai-subhub/releases/latest` (User-Agent set, 20 s timeout, HTTPS only also across redirects). Tag `vX.Y.Z`; assets by name `ai-subhub.exe` and `ai-subhub.exe.sha256` (first token = hex digest, a file name after it is fine). Only a version newer than the running `CARGO_PKG_VERSION` is offered; a draft, pre-release, 404 or no release is "up to date", not an error. The repo must be public for unauthenticated checks.
- **Settings -> Updates** (top menu, after Statistics): Update mode chips (Auto / Manual, default Manual), current version, "Last checked …" with **Check now**, and a status block: "Update available: vX.Y.Z" with **Install** (Auto: "Install now"), progress, or a safe error ("Could not check for updates: no connection", "Download failed: HTTP 404", "Cannot update in this folder: access is denied"). Saved on change as `updates { mode, last_check, last_seen_version }` (`#[serde(default)]`; test `older_files_without_updates_still_load`).
- **Schedule** (both modes): first check ~1 min after start, then every 6 h, 30 min after a failed one (`update::check_due`). Manual shows a tray balloon once per version. Auto downloads at once into `%LOCALAPPDATA%\AI SubHub\updates\ai-subhub-X.Y.Z.exe` (`.part` while loading; a verified copy is reused) and installs when `Busy` is idle, tried every minute.
- **Idle** (`update::Busy`, Auto only): no popover, Settings, Statistics or "Updated" window open, no sign-in running (`AppState::signing_in`), no popover top-edge drag (`AppState::popover_dragging`, only counts while the popover is open). A Manual Install ignores this.
- **Install**: download (or reuse) and verify SHA-256 (mismatch: file deleted, error shown) -> `<exe>.old` rename of the running exe -> copy the download to the original path -> start it with `--updated-from <old version> --wait-pid <pid>` -> quit. Copy failure rolls the rename back; if the new exe cannot start the swap is reverted and the old one keeps running. The new process waits for the pid (30 s) before the single-instance mutex and the tray, then deletes `<exe>.old` and stale files in the updates folder in a background thread. The exe path stays the same, so Start with Windows (HKCU Run) keeps working.
- **Development builds** (exe path has a `target` folder followed by `debug` or `release`, or the path is unknown): checking works, installing never; the page says "Development build: updates are off".
- **Patch notes**: `CHANGELOG.md` in the repo root, embedded with `include_str!`; `## X.Y.Z – date` plus 3-6 short bullets per version, `## Unreleased` ignored. After an update (`--updated-from`, or `last_seen_version` older than the running version) a small frameless dialog "Updated to vX.Y.Z" lists the bullets of every version since `last_seen_version` (newest first, skipped ones too) with OK (Enter and Esc also close it). `last_seen_version` is saved when the dialog opens. A fresh install (empty value) only records the version; no notes for the versions in between means no dialog.
- **Release**: `scripts/release.ps1 -Version X.Y.Z [-Publish]` (see CLAUDE.md, "Releasing").
- Tests never touch the network, the real exe or the real updates folder; the swap order and rollback run against a fake file system.
